CTFshow pwn141：通过 UAF 覆盖 note 函数指针

这篇记录我做 CTFshow pwn 141 的过程。题目是一个 32 位 note 菜单程序，开启了 Canary 和 NX。利用点不在栈溢出，而在 note 结构释放后，notelist 仍保留旧地址。我们通过堆块复用，让新 note 的内容区落到旧 note 结构上，再把结构里的函数指针改成 use，最后通过打印菜单触发间接调用。

这题最开始让我绕晕的不是 payload，而是几个地址和分配动作混在了一起：一次 add 里到底申请几次、为什么调用两次 add(32, ...)、add(8, p32(use)) 的两次分配分别拿到谁、以及 show(0) 为什么会跳到 use。下面按源码执行顺序把这些问题讲清楚。

附件 ctfshow141

保护和利用目标

题目是 i386，也就是 32 位程序。题目检查结果显示开启 Canary 与 NX。这里没有利用栈溢出覆盖返回地址，因此 Canary 和 NX 不是这条利用链的关键；我们利用的是堆上的悬空指针和函数指针调用。

程序有四个菜单操作：Add、Delete、Print、Exit。二进制里还有 use 函数。目标是让 print_note() 在处理某个 note 时调用 use。

  3. 这个字段已被 p32(use) 改成 use 的地址。

这题我问过的问题

一次 add 不是已经申请了两块吗，为什么前面还要 add 两次？

一次 add 确实申请两块：一个 8 字节 note 结构，一个 size 字节内容区。前面调用两次，是为了创建 N0、N1 两个 8 字节结构块；后面的 add(8, ...) 自己又需要两次 8 字节分配，分别给新结构和新内容区使用。

add(32, b"aaaa") 里的 32 是什么？

它是内容区的申请大小。note 结构仍固定申请 8 字节；内容区申请 32 字节。发送的 aaaa 只有 4 字节，两者不是一个概念。

add(32, ...) 总共是不是 40 字节？

按两次 malloc 的请求大小相加，是 8 + 32 = 40 字节；但这是两块独立分配，不是一整块连续的 40 字节。堆分配器实际占用还会涉及 chunk 头和对齐。
N0 和 N1 为什么会“连起来”？
它们不需要在物理内存中相邻。N1 → N0 说的是同尺寸空闲链表中的复用顺序。调试时要根据实际地址确认，不要把链表链接和物理相邻混为一谈。
add(8, p32(use)) 的第一次和第二次 malloc 分别做什么？
第一次取回 N1，作为新 note 结构；第二次取回 N0，作为新内容区。p32(use) 写到 N0 的开头，覆盖旧 note 0 的函数指针。
为什么 show 后会跳到 use？
因为 print_note() 把 notelist[0] 指向的结构开头当函数指针调用。结构开头已经被改成 use 的地址，所以间接调用进入 use。
