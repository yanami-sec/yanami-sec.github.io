这篇记录从观察普通堆分配开始，逐步走到 House of Force。过程里我先在 GDB 里认出 top chunk，再用越界写修改它的 size，最后通过菜单里的 add/edit 把一次 malloc 导向栈上的函数指针，并调用 win。

x86-64 下，malloc 返回的是用户区指针，chunk 头通常在它前面 0x10 字节

size 字段低位包含标志。0x31 去掉低位标志后是 0x30，表示 chunk 总大小为 0x30；0x41 去掉低位标志后是 0x40。

top chunk 是什么，malloc 如何移动它

top chunk 是当前 arena 中位于已分配 chunk 末尾、可继续切分的空闲 chunk。每次从 top 分配普通 chunk，top 的头部就向高地址移动，size 随之减少。

这也解释了为什么我在 pwndbg 输入 vis_heap_chunks 得到 Undefined command：我的环境里没有这个命令。用 x/gx、x/4gx 和变量地址一样可以直接观察 chunk。

按我的最终脚本走完整条利用链

下面按我实际使用的脚本说明。它先创建 slot 0 并覆盖 top size，再计算 request，通过两次 add 将 slot 2 放到 callback 字段，最后 edit 函数指针并触发菜单选项 3。

这段脚本逐步做了什么

  1. process 启动 hof_menu；程序启动时打印 callback target。脚本把它解析为 callback_addr。它是栈上 target.callback 字段的地址，不是函数地址。
  2. add(0, 50) 申请 slot 0。50 是十进制请求大小；这次 glibc 将 chunk 规格化为 0x40。add 返回 malloc 用户区地址 slot0。
  3. top = slot0 + 0x30。chunk 头在 slot0 - 0x10，chunk 总大小为 0x40，因此 top 头在 slot0 - 0x10 + 0x40，也就是 slot0 + 0x30。
  4. payload 总长 0x40：前 0x30 个 A 填到 top 头前，8 个 B 覆盖 top 的 prev_size，最后 8 字节把 top size 改成 0xfffffffffffffff1。edit(0, 0x40, payload) 用菜单 edit 完成越界写。
  5. request = callback_addr - top - 0x20。大申请从当前 top 开始，第一次 add 把新的 top 头推到 callback_addr - 0x10；下一次 add(2, 0x20) 返回的用户区地址就应为 callback_addr。
  6. add(1, request) 消耗大块；add(2, 0x20) 取得落点。建议紧跟着检查 slot2 == callback_addr，确认落点无误再写。
  7. edit(2, 8, p64(elf.sym[“win”])) 把 win 的地址写到 callback 字段。程序是 no-PIE 编译，因此 ELF 中 win 的地址可直接使用。
  8. gdb.attach(p) 在触发前附加调试器；菜单选择 3 后执行 target.callback()，控制流进入 win，再由 system(“/bin/sh”) 启动 shell。
    这个脚本的 edit helper 使用 p.sendline(payload)。read_exact 只读取指定的 0x40 或 8 字节，所以 sendline 额外发出的换行会留在输入流里，可能让菜单多走一轮空输入/Invalid choice。更稳妥的写法是把 edit helper 最后一行改为 p.send(payload)，避免多发换行。

这次练习中容易混淆的点

申请大小、chunk size 和 top 偏移不是一回事

  • malloc(0x20) 的 chunk size 是 0x30，top header = p + 0x20，top size = p + 0x28。
  • malloc(50) 的 chunk size 是 0x40，top header = p + 0x30，top size = p + 0x38。
  • 50 是十进制 50，不是 0x50，也不是 0x20。

top、target、request、first、land 的区别

  • top：当前 top chunk 的头部地址。
  • target：希望第二次 malloc 返回的用户区地址。
  • request：第一次大 malloc 的申请长度，不是地址。
  • first：第一次大 malloc 返回的用户区地址。
  • land：第二次小 malloc 返回的用户区地址；成功时 land == target。

地址只能混用在同一次进程运行里

ASLR 会让堆和栈地址变化。不能用上一次运行的 callback_addr 配本次运行的 slot0 地址。每次启动都重新接收两者并计算 request。

没有读到 menu 提示时，先检查交互顺序

程序按菜单顺序等待 choice、Index、Size 或 Length、Data。脚本如果遗漏 Index/Size 就去等待 slot 地址，会造成看似卡住的情况。先对照程序实际提示逐步收发。

总结

我这次从 top chunk 的物理位置开始，逐步确认了 House of Force 的利用条件和分配过程：

最关键的是先用 GDB 根据 chunk size 算出 top 的真实头部地址。然后把地址关系分清：第一次大申请负责移动 top，第二次小申请才负责落到 target。整个菜单利用中，地址和长度都由我从程序输出及当前运行的堆布局计算，而不是让 C 程序替我完成。
