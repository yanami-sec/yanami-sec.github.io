先理解 Linux 如何处理信号

程序运行时如果收到信号，Linux 内核大致会

  1. 暂停当前执行；
  2. 在用户栈上保存当前寄存器等上下文；
  3. 跳到信号处理函数；
  4. 信号处理函数结束后，通过 rt_sigreturn 恢复原来的上下文；
  5. 从被中断的位置继续执行。
    这个保存的上下文就是 signal frame。它包含了寄存器、栈指针、指令指针等信息。内核的 rt_sigreturn 会根据这个 frame 恢复执行状态。
    正常程序由内核创建、使用这个 frame。SROP 则设法让程序把攻击者准备的数据当作 frame，让内核恢复攻击者指定的寄存器。

系统调用和普通函数调用的区别

ORW 中的 open、read、write 可以作为 libc 函数调用，也可以直接发起 Linux 系统调用。SROP 教程通常选择直接做系统调用。

系统调用约定和普通函数调用约定不完全一样。比如普通函数的第四个参数使用 rcx，但 Linux amd64 系统调用的第四个参数使用 r10。

一个 frame 只能在一次 rt_sigreturn 中恢复一组寄存器状态。本题的第一份 frame 用来执行 read，第二份 frame 用来执行 execve。

第一阶段：把 /bin/sh 写到 BSS

用 pwntools 的 SigreturnFrame 构造内核恢复寄存器时要读取的数据

这里各字段的含义：

  • frame.rip：rt_sigreturn 恢复完寄存器后，从哪里继续执行。设为 syscall\n\tjmp main，恢复后就会再次执行 gadget 里的 syscall，这次执行 read。
  • frame.rsp：恢复后的栈指针。read 返回后 gadget 会跳到 main，main 和它调用的函数还需要一个有效栈，所以要把 rsp 指向可写的 BSS 区域。

bss_addr 和 fake_stack 用途不同：前者存放 /bin/sh\x00，后者提供重新进入 main 后使用的栈空间，二者应当分开。

第一份 payload 的栈布局

第一阶段的 payload 大致是

控制流如下

  1. vuln 执行 ret，跳到 gadget_pop_rax。
  2. pop rax 取出 15，即 rt_sigreturn 系统调用号。
  3. ret 跳到 gadget_syscall_jmp_main。
  4. gadget 中的 syscall 执行 rt_sigreturn。
  5. 内核把栈上的 SigreturnFrame 当作寄存器现场恢复，设置 rax=0、rdi=0、rsi=bss_addr、rdx=8、rip=syscall_gadget 等。
  6. 恢复后从 syscall_gadget 开始执行。它的 syscall 现在执行 read(0, bss_addr, 8)。
  7. read 收到 /bin/sh\x00 后返回，随后 gadget 执行 jmp main。

要注意：SigreturnFrame 是给内核读取的数据，不是 CPU 逐条执行的指令。触发 SROP 的 syscall 指令已经在 gadget 里了；frame 的 rip 则决定恢复后从哪里继续执行。

为什么 frame.rsp 也要设置

rt_sigreturn 恢复的不只是 rax、rdi、rsi、rdx 和 rip，还包括 rsp。
第一次 SROP 完成后，程序会执行：

jmp 不会像 call 一样自动压入返回地址。重新进入 main 后，函数还会建立栈帧并调用 vuln，所以必须确保恢复的 rsp 指向一段有效、可写的内存，并且栈对齐符合函数入口约定。否则即使 read 成功，跳回 main 后也可能崩溃。
bss_addr 是路径字符串的位置；fake_stack 是重新进入程序后用作栈的位置。两者应该分开规划。

没有jmp main怎么办

没有 jmp main 时，需要给第一次 SROP 准备一条返回到 main 的后续控制流。常见做法是让 syscall 后执行 ret

不过，光把 gadget 换成 syscall; ret 还不够：ret 会从当前 rsp 指向的位置弹出下一条地址。因此需要同时布置好返回地址。

对于这题，第一份 frame 恢复后执行 read。read 返回时会继续执行 syscall; ret 里的 ret。可以让 frame.rsp 指向 BSS 中预先放好的一个指针，而这个指针是 main 的地址

但这个伪代码有个重要的时序问题：第一次 SROP 的 read 也要读 /bin/sh，不能同时把 main 地址写到另一个 BSS 位置，除非额外安排一次写入或让第一次 read 的目标布局同时包含两者。
一个简单的布局是让第一次 read 把路径和返回地址一起写入 BSS

执行过程是

  1. rt_sigreturn 恢复到 syscall; ret。
  2. gadget 的 syscall 执行 read(0, path_addr, len(stage_data))。
  3. read 把 /bin/sh\x00 和 main 地址一起写进 BSS。
  4. read 返回，执行 ret。
  5. ret 从 frame_read.rsp 指向的位置取出 main 地址并跳过去。
