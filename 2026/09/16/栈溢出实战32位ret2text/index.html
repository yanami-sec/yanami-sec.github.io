为什么我们需要win地址？

可以回忆一下我们以前所学的，函数返回的时候会执行ret，而ret是什么呐，是cpu做pop eip呀，也就是从栈顶拿4个字节。

输入


地址是0x08049196，为什么需要这个地址，因为后面我们需要栈溢出
正常情况下：

  • call test 的时候，CPU 自动把 main中test调用后的下一条指令地址 保存到栈里。
  • ret 时取出来，所以程序回到 main 继续运行。
    但是栈溢出以后：
  • 我们通过 gets() 输入过长数据。
  • 把原来的返回地址覆盖掉了。
  • 换成了我们想执行的地址，比如 win() 的地址。
    所以原本返回地址 = main继续执行的位置
    现在变成：
    返回地址 = win函数地址
    当 ret 执行时：取出返回地址 → 放入EIP
    于是：EIP = win地址
    CPU 接下来就会执行 win()。

在栈溢出利用中，我们需要知道从输入缓冲区（buf）开始，到返回地址（return address）之间的距离，也就是 offset。如果直接使用 AAAA 这类重复字符进行测试，虽然可以看到 EIP=0x41414141，但是无法判断到底是第几个字符覆盖了返回地址。因此 pwntools 提供了 cyclic() 函数生成一段具有唯一规律的字符串，例如 aaaabaaacaaadaaa...，当程序崩溃后，通过查看 EIP 中被覆盖的4字节数据，再使用 cyclic_find() 查找该数据在字符串中的位置，就可以准确计算出覆盖返回地址所需要的字节数。例如 EIP 被覆盖为 0x61616167，对应字符串中的 gaaa，通过 cyclic_find() 得到偏移为28，说明输入28个字节后正好到达返回地址。简单来说，cyclic 的作用就是帮助我们精准定位返回地址的位置，而不是用于最终攻击。
