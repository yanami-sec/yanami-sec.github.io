House of Einherjar：从源码分析到 callback 劫持

这篇记录的是我在本地 test6 完成的 House of Einherjar 练习。目标是通过伪造 chunk 元数据，让 free(b) 向后合并；再申请重叠块，改写 B 里的 callback，最后通过保留下来的旧指针调用 win()。
程序使用本地 glibc 2.27。利用分为四段：读源码、自己申请相邻 chunk、伪造 chunk 并触发合并、覆盖 callback 并调用。

先看 C 源码

从结构体看 callback 的偏移

Note 结构体布局：

所以 callback 地址是 B 的用户区指针加 0x10。这里的 B 指 malloc 返回的用户指针，不是 chunk 头地址。

函数里找漏洞

  • add() 根据用户提供的 size 调用 malloc，并把返回指针存在 slots[index]。
  • edit() 允许用户指定 length，只限制它不超过 0x1000，没有限制它不超过原申请大小。因此可以从 a 写出边界，修改后续 chunk 头。
  • delete() 调用 free，但没有把 slots[index] 清零，释放后留下旧指针，形成 UAF。
  • use_callback() 把 slot 当作 Note，调用 note->callback()。如果能改 callback，就能控制间接调用目标。

把菜单操作和 pwntools 函数配对

菜单 C 函数 exp.py 函数
1 add() add(idx, size, data)
2 edit() edit(idx, size, data)
3 delete() delete(idx)
4 use_callback() getshell(idx)

pwntools 函数只是按照 C 程序提示发送菜单和参数。发现漏洞时，仍要回到对应 C 函数看具体读写行为。

add() 的接收顺序

C 的 add() 顺序是：读 index、读 size、malloc、打印 slot 地址、读初始数据长度、再读初始数据。所以 exp 必须先接收地址，再发送初始数据长度。否则 sendlineafter 会把 slot 地址行一起读走，后面再等 slot 地址就会卡住。

int(…, 16) 把十六进制地址文本转成 Python 整数，return addr 使后面可以计算 fake = a + 0x110。read_exact 按固定长度读原始字节，所以堆数据使用 p.send(data)，不要额外发送换行。

第二段 payload：覆盖 B 的 callback

B 的用户指针是 b。结构体中 callback 位于 b + 0x10。重叠块用户区从 a + 0x120 开始：

所以第二段 payload 是 0x400 字节填充，随后写 win 地址：

这次覆盖的是 B 的 callback。重叠块只是让我们能从另一块的起点写到 B 的字段。
之前错误的第二段 payload 在偏移 0x3f0 开始写 chunk 样式的数据，又在 callback 前放了 0x10 字节填充；而且申请大小用成 0x910，因此实际写到了 top chunk 区域，不是 B 的 callback。

通过旧指针调用 callback

delete(1) 之后，slot 1 仍保存 B 的旧地址。程序的 use_callback() 不知道 B 已释放，仍从旧地址读取 callback 并调用。callback 已经被重叠写成 win，所以执行到 win() 并启动 /bin/sh。

完整利用链

这题把 chunk 头、prev_size、PREV_INUSE、unlink、向后合并、重叠分配和 UAF callback 串成了一条利用链。调试时每一步都核对具体地址和字段，比只看最终是否拿到 shell 更容易定位错误。
